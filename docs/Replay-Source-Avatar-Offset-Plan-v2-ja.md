# コピー元アバターのHMDオフセット・ON/OFF・設定保存：設計計画書 第2版

作成日：2026-09-13。対象：MovementRecorder `BS1.29.1`。

状態：ユーザーの「OKです進めてください」を受けて実装。結果は `Replay-Source-Avatar-Offset-ja.md` に記載する。

第1版を残して本書を追加した。ユーザーの追加指定に従い、アバターのオフセット処理をON/OFFできる設定と、オフセット値の保存を設計に含める。第1版の「追加の設定項目は設けない」は本書で置き換える。

2026-09-13追加指定：「0.5m単位ではなく0.1m単位」に合わせ、鑑賞設定と再生中の操作パネルのXYZ調整を0.1 m刻みに変更する。上下限と保存済みの値を維持し、操作時に0.1 mの整数倍付近へ残る浮動小数点の微小誤差を補正して、0に戻した際の専用処理省略も維持する。

## 操作と動作

- リプレイメニューの「鑑賞設定」に「コピー元アバターにHMDオフセットを適用」を追加する。「コピー元アバターを表示」の近くに配置する。
- 初期値はOFFとする。表示とオフセット適用の両方がONの場合に、コピー元アバターの表示位置へ鑑賞用HMDと同じX・Y・Z値を加える。
- オフセット適用がOFFの場合も、HMDとUIは設定した鑑賞位置に移動する。コピー元アバターはアバターMODが更新した位置で表示する。
- コピー元アバター自体の表示がOFFの場合は、オフセット処理も実行しない。オフセット適用の設定値は保持し、再び表示ONにしたときに利用できるようにする。
- オフセット適用のON/OFFは鑑賞設定で変更し、次のリプレイ開始時に反映する。既存のコピー元表示設定と同じタイミングでセッションに取り込む。
- X・Y・Zは既存の「鑑賞位置」の値を共用する。アバター専用の別座標は設けない。再生中の位置調整にも追従する。
- 表示位置は「アバターMODが更新したワールド座標 ＋ HMDの鑑賞オフセット」とする。例えばZが−2 mなら、HMDとコピー元アバターを同じ方向へ2 m移動して表示する。
- 一時停止・シーク中も、コピー元は現在のプレイヤーに追従しながらオフセット先に表示する。記録動作を再生する複製アバターは記録された位置で再生する。

## OFF時の負荷軽減

- 実行条件は「コピー元表示ON、オフセット適用ON、オフセットが0以外」とする。
- 条件を満たさない場合は、オフセット専用の管理オブジェクト・コンポーネントを生成せず、専用の対象階層探索や座標保存用配列の確保を行わない。
- `Camera.onPreCull`、`Camera.onPostRender` のオフセット用コールバックを登録しない。オフセット用のフレーム境界処理や復元コルーチンも動かさない。
- 各フレームの座標保存・移動・復元を実行しない。既存の表情同期・表示制御・リプレイ再生処理はそれぞれ必要な処理として継続する。
- 再生中にX・Y・Zをすべて0にした場合は、残っている移動を復元して専用処理を解除する。再び0以外に変更したときに、セッションのON/OFF設定に従って準備する。条件の再評価は位置変更やモデル再準備の時点で行う。

## 設定ファイルへの保存と復元

既存のBSIPA設定ファイル `UserData/MovementRecorder.json` に、次の項目を追加する。

| 項目 | 型 | 初期値 | 内容 |
| --- | --- | --- | --- |
| `offsetReplaySourceAvatarWithHmd` | bool | `false` | コピー元アバターへのHMDオフセット適用 |
| `replayObserverX` | float | `0` | 鑑賞位置・左右、m |
| `replayObserverY` | float | `0` | 鑑賞位置・上下、m |
| `replayObserverZ` | float | `-2` | 鑑賞位置・前後、m |

- ON/OFFと各軸の値は、既存の `PluginConfig` の保存対象プロパティとして扱う。
- リプレイメニューの鑑賞設定と、再生中の操作画面の両方について、値を変更した時点で設定にも反映する。ファイルへの書込みは既存のBSIPAの保存機構を使用し、描画処理内から書き込まない。
- 次回起動・メニュー表示時に保存した値を読み込み、設定画面と次のリプレイの初期位置に反映する。リプレイを終了しても0・0・−2へ戻さない。
- 読み込み開始時に設定をセッションへ取り込む。読み込み中の画面操作は既存どおり無効にし、設定ファイルの外部変更によって実行中のリプレイ位置やON/OFFが突然変わらないようにする。
- アバターのオフセット適用がOFFの場合もX・Y・Zの保存・復元を行い、HMDの鑑賞位置を再現する。
- 新しい項目がない既存の設定ファイルでは初期値を使う。座標は有限値を検証し、既存UIの範囲（X：−5〜5 m、Y：−3〜3 m、Z：−8〜5 m）に収める。不正な数値はその軸の初期値へ戻す。
- 毎フレームの設定保存は行わず、設定変更時だけ保存対象を更新する。

## 表示位置を移動する方式

- 有効時のみ `SourceAvatarOffset` を作成し、既存のAvatar判定からコピー元のメッシュと、そのスキニングに必要なボーンを特定する。
- `Camera.onPreCull` で描画直前の座標を保存し、コピー元へオフセットを適用する。`Camera.onPostRender` で描画前の座標へ戻す。Animator・IK・揺れ物には元の座標で更新させる方針とする。
- 上記の処理点は第1版で調査したUnity標準の描画コールバックを使う。[Unity: onPreCull](https://docs.unity3d.com/2021.3/Documentation/ScriptReference/Camera-onPreCull.html)、[Unity: onPostRender](https://docs.unity3d.com/2021.3/Documentation/ScriptReference/Camera-onPostRender.html)。
- HMD・Camera2・CameraPlus・床ミラーから同じ位置に見えるようにする。特定のカメラMODへのアセンブリ参照は追加しない。
- ミラーなどによる入れ子の描画ではオフセットを一度だけ加算し、外側の描画終了時に復元する。描画終了通知が欠けた場合はフレーム境界にも復元経路を設ける。
- メッシュとボーンを同じ量だけ動かす。同じ親の実HMD・実セイバー・UI・Otherを巻き込まないよう、対象階層と除外する子階層の境界を扱う。
- 親子をそれぞれ移動する場合も、描画前に保存した座標を基準にして二重加算を防ぐ。親子関係・回転・スケール・レイヤー・描画材質は維持する。
- モデル再準備、オフセット0への変更、失敗、終了、破棄時には移動を復元してコールバックを解除する。消失したTransformは既存のモデル消失処理へ引き継ぐ。

## 変更予定ファイル

- `Configuration/PluginConfig.cs`：ON/OFFとX・Y・Zの保存項目・初期値・読み取り検証。
- `Playback/ReplaySession.cs`、`UI/ReplayMenuService.cs`：保存値の初期反映と、読み込み開始時の設定取り込み。
- `UI/ReplayFileViewController.cs`・`.bsml`：鑑賞設定のON/OFF追加、配置調整、X・Y・Z変更時の保存。
- `UI/ReplayControlsViewController.cs`：再生中に変更したX・Y・Zも設定へ保存。
- `Playback/Models/SourceAvatarOffset.cs`：描画前後の移動・復元、入れ子描画、後始末。
- `Playback/Models/ModelBinding.cs`、`RenderModelClone.cs`：必要な場合だけオフセット対象の情報を準備。
- `Playback/Runtime/PlaybackRuntime.cs`、必要に応じて `SpectatorRig.cs`：実行条件による生成・解除、現在のHMDオフセットの受け渡し。
- テスト、API照合スクリプト、日本語の使い方・実装報告、確認用ZIPの文書一覧。

## 検証と成果物

- 表示ON/OFFとオフセットON/OFFの全組合せを確認する。OFF時は専用オブジェクト・描画コールバック・定期処理がなく、座標の読取り保存・変更が実行されないことを検証する。
- 0との切替、XYZの組合せ、親の回転・スケール、メッシュと兄弟階層のボーン、複数アバター、Avatar内のOther・セイバーを確認する。
- 複数カメラと入れ子描画、連続フレーム、ポーズ・シーク、再準備・終了・例外で、二重適用や位置の残留が起きないことを確認する。
- メニューと再生中の両画面で変更した値について、保存項目への反映と新しいセッションへの復元を確認する。既存設定の項目欠落、不正数値、範囲外の値も検証する。
- 表示・表情同期・レイヤー・Camera2連携の既存テスト、Releaseビルド、導入済みDLLのAPI照合を行う。
- 実機ではHMDとの位置一致、体・顔・手足・揺れ物、外部カメラと床ミラー、通常プレイへの復帰、ゲーム再起動後のON/OFFとXYZ復元を確認する。実機の描画や保存の確認結果は、自動テストと区別して記載する。
- 承認後に実装・検証し、動作確認用DLLとZIPを作成する。コミットは別途依頼された時点で行う。
