# ポーズパネルと観客用ポインターの修正

更新日：2026-09-12

ユーザー環境でアバターと既存セイバーの再生を確認できた。一方、再生中も操作パネルが表示され、ポーズすると手元のポインターで操作できない問題が残った。

## 調査と修正方針

修正前の実装は、シーン内で見つけたVRPointerの左右参照を裸のVRControllerへ交換し、EventSystem.enabledだけを有効化していた。標準のポーズメニュー表示を通さないため、親階層の非アクティブ状態、VRInputModuleの有効状態、EventSystem.currentを保証できない。メニュー用コントローラーの見た目もコピーしていない。また、手の座標は標準ポーズメニューの親を基準にしており、実HMDカメラと同じ追跡原点を使っていなかった。これらはコードから確認した不備であり、問題発生時の各オブジェクトの有効状態を実機で取得した結果ではない。

BeatLeaderのMenuControllersManagerは標準メニュー用コントローラーを再利用し、InputSystemTweakは独立したEventSystemを現在の入力先にする。ScoreSaberのImberUIPositionControllerもメニュー用コントローラーを使い、観客位置に合わせて移動させる。これらを参考に、次の修正を行う。

1. 再生中はパネルと観客用の操作系を非表示にする。ポーズ時に表示し、「再開」でまとめて隠す。停止したまま操作系だけが消える「パネルを閉じる」は廃止する。準備に失敗した場合や再生完了時は、停止状態で復帰・退出できる操作系を表示する。
2. シーンに注入されたVRInputModuleから対応するVRPointerを取得する。通常メニューの左右コントローラーをコピーし、標準のコントローラー表示を保つ。これはUIのコントローラーだけを対象にし、Saberを含むオブジェクトの複製は拒否する。
3. 専用のEventSystem、VRInputModule、VRPointerを非アクティブなルートに構築し、標準ポインターのレーザー・カーソル設定とハプティクス設定を引き継いでから有効化する。表示時にEventSystem.currentを指定する。VRPointerは左右切替の状態をstaticフィールドに保持するため、元のEventSystemだけでなくVRInputModuleとVRPointerも一時的に無効化して競合を防ぐ。非表示・終了時に以前の入力先と各コンポーネントの有効状態を戻す。通常のポーズメニューの親やAnimatorに依存しない。
4. 左右のUIコントローラーには実HMDカメラと同じ追跡原点・鑑賞オフセットを使う。UIの判定前に追跡姿勢を更新する。FPFCでは鑑賞カメラを基準にしたマウス操作を維持する。
5. 最新ログで繰り返される「Cannot set field of view ... while VR is enabled」は、VR描画中にFOVを書き換えないよう修正する。平面描画中だけFOVとアスペクト比を同期する。

セイバーの駆動・トレイル、アバターのコピー再生、HDTの処理、manifestのgameVersionは変更しない。

## 検証

製品の観客リグ・入力処理をテスト用のUnityオブジェクトで動かし、通常メニューの親が非アクティブでもUIを有効化できること、入力先の切替・復元、部屋の移動・回転と鑑賞オフセットを含む手の追跡、FPFC切替、VR中のFOV書換禁止、セイバー非複製を確認する。パネルの表示・非表示の呼出し箇所とBSMLも照合する。

Releaseビルド成功、自動テスト65件成功、導入済みゲームDLL・依存DLL・BSML等の197項目の照合に成功した。標準側のポインター／入力モジュールの有効・無効4通りについても、ポーズ中の競合回避と復元を確認した。パネルの初期非表示、再開時の非表示、停止中の表示制限、閉じるだけのボタンを廃止したことはコードとBSMLで確認した。既知のMSB3277参照競合警告は残る。

自動試験は本物のXR入力・描画・Unityのイベント実行を再現しない。実機では「再生中は非表示→メニューボタンでポーズ→手元のポインターで操作→再開で非表示→再度ポーズ→曲選択へ戻る」を確認する。
