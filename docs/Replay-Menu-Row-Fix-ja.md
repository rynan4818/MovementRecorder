# リプレイ一覧の選択色と1行表示の修正

日付：2026-09-13。対象：MovementRecorder `BS1.29.1`、Beat Saber 1.29.1、BSML 1.6.10。

ユーザーの画像では、選択行の頭の移動距離と選択ファイル名は水色になる一方、左側の日時・記録情報は白いままで、「選択中」の文字も反映されていなかった。導入済みMovementRecorder.dllのSHA-256は直前の検証用DLLと一致していた。

## 修正内容

- 日時・記録秒数・対象数・サイズを1行にまとめ、頭の移動距離を右端に配置した。行の高さは維持し、長い文字列の折返しを無効にした。
- 行の文字更新を、個々のプロパティ変更通知から実際の文字コンポーネントへの書き込みに変更した。選択変更時、セル生成後、BSMLのセル描画イベントから、左側の情報と右側の距離を同じ選択状態で更新する。
- 選択中の行には水色と「選択中」を表示する。別の行を選択すると以前の行を通常色へ戻し、スクロールで作り直されたセルにも現在の選択を反映する。
- 選択状態はメニューサービスで管理する。読み込み中の無効なクリックや、更新前の古いセルのイベントで選択色だけが別の行へ移ることを防ぐ。

導入済みBSMLの `CustomCellTableCell.RefreshVisuals` が `refresh-visuals` アクションへ選択・ホバー状態のboolを渡すことと、セルごとの解析でUIComponentを割り当て、`post-parse` を呼ぶ処理を確認した。左側の通知が反映されなかった実機内部の詳細は取得していないため、根本原因をBSMLだけに断定せず、この通知経路に依存しない更新へ変更した。

## 検証

- Releaseビルド成功。既存のMSB3277参照バージョン競合警告は残る。
- 自動テスト109件成功、失敗・スキップ0件。既存の選択テストを、左右の文字更新、元の行の通常色への復帰、セル再生成後の選択表示、無効なセルイベントの確認へ更新した。
- 導入済みDLL・API照合246項目成功。行のUIComponent型、セル描画イベントの引数、文字・色のsetterを確認した。
- manifestの `version=0.2.4`、`gameVersion=1.20.0` を維持。
- 実機での表示確認は未実施。テストは文字コンポーネントの代替実装を使用し、HMD上の幅・字体・描画は再現しない。

検証記録：`artifacts/tests/menu-row-fix.trx`、`artifacts/build-menu-row-fix.log`、`artifacts/contracts-menu-row-fix.json`。
