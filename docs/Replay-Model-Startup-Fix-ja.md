# モデル準備で曲が開始しない問題の修正

更新日：2026-09-12

## 原因と修正範囲

`Logs/2026.09.12.20.33.17.log` の20:34:19（4190行目）と20:35:00（4457行目）で、セイバーモデル `nagisaber2_b (1)/Cube` の `TrailRenderer` を検出した `RenderModelClone.CopyRenderers()` が例外を出していた。モデル準備が完了しないため、曲開始前の一時停止が解除されなかった。

MeshRenderer／SkinnedMeshRendererで描画できるモデル本体をコピーし、TrailRenderer・LineRenderer・ParticleSystemRenderer等の未対応描画だけを省略する。省略内容は種類とパスをログに残し、操作パネルにも省略があることを表示する。未対応描画だけで構成され、再生できるメッシュがないモデルは、理由を表示して対応設定で扱う。

省略したRendererも元モデル側では一時的に描画を隠し、終了・準備失敗時に元の状態へ戻す。LOD参照では意図的に省略したRendererを除去し、モデル外への参照は従来どおりエラーとする。記録されていないエフェクトの履歴を生成・再現する機能は追加しない。

同ログ4461行目以降では、対応設定の候補一覧が既に破棄されたTransformに触れて失敗していた。シーンの探索結果を利用するときにUnityの消失判定を行い、古い候補を除外する。

HDT／HDT Counterへの介入は追加しない。ゲームのスコア等の除外範囲とmanifestの `gameVersion = 1.20.0` を維持する。

## 検証方法

製品のモデルコピー・モデル探索コードをテスト用のUnityオブジェクトで実行し、メッシュと追加描画の混在、LODの省略参照、元の描画状態の復元、失敗時の後片付け、古い探索候補の除外を確認する。これは描画やUnityのフレーム実行を検証するものではない。

Releaseビルド、既存データテスト、導入済みDLL・BSMLとのAPI照合も実施する。最終結果は [実装・検証報告](Replay-Implementation-ja.md) に記載する。

実機では、同じ記録から曲・モデルが開始すること、必要なモデル本体が見えること、一時停止・シーク・退出と次の通常プレイが動くことを確認する。省略した軌跡等は表示されない。
