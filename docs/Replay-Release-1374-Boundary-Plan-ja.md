# 1.37.4で判明した追加境界と対応案

2026-09-13。第2版への追加。ユーザー回答で5ブランチ・0.3.1を2種類のZIPとする推奨案が承認されました。

## 確認できた差分

1.37.1向けのリプレイ移植はReleaseビルドと164件のテストに成功しました。ただし、同じDLLの呼び出し署名を1.39.1の実DLLと比較すると、HMUI.FlowCoordinator / HMUI.ScreenおよびSaber.movementDataの参照が解決できません。

- 1.37.1ではFlowCoordinator / ScreenはHMUI.dll、1.37.4以降ではBeatSaber.ViewSystem.dllにあります。名前空間が同じでも継承先のアセンブリが異なるため、開始APIのオーバーロードを共通にするだけでは対応できません。
- 1.37.4以降のSaberではmovementDataがmovementDataForLogic / movementDataForVisualEffectsへ変わっています。
- 事前調査では型名・引数を中心に比較しており、UIの定義アセンブリ移動を見落としていました。先の「1.37.1～1.39.1を1つのDLL」という案を修正します。

## 推奨案

5ブランチとし、0.3.1だけ2つの標準ZIPを同じGitHubリリースへ添付します。MOD番号とリリース全体の対応範囲は指定を維持します。

| ブランチ | MOD | 対応範囲 | manifest.gameVersion |
| --- | --- | --- | --- |
| BS1.29.1 | 0.3.0 | 1.29.0-1.29.1 | 1.29.0 |
| BS1.37.1 | 0.3.1 | 1.37.1-1.37.3 | 1.37.1 |
| BS1.37.4（追加） | 0.3.1 | 1.37.4-1.39.1 | 1.37.4 |
| BS1.40.0 | 0.3.2 | 1.40.0-1.40.8 | 1.40.0 |
| main | 0.3.3 | 1.42.0-1.44.1 | 1.42.0 |

Git操作はBS1.37.1の移植コミットからBS1.37.4を作成し、UI参照とセイバー取得を専用コードへ変更してコミットします。その後BS1.40.0へ引き継ぎます。タグや公開操作は行いません。ZIP名は各プロジェクトのModding Tools標準名のままです。

## 他の選択肢

- 4ブランチを厳守して0.3.1を1.37.4-1.39.1に限定する。1.37.1の利用者約30人を今回の新リプレイ対象から外すことになります。
- 4ブランチのまま、1.37系に同じソースを参照するVisual Studioプロジェクトを2つ用意する。互換用の実行時分岐は避けられますが、manifestと参照DLLのビルド設定が2組になります。0.3.1のZIPは2つ必要です。

1.29系・1.40系・mainの版番号と対応範囲、Legato非採用、将来のBS1.42.0切り出し、既存形式のリリース文作成方針は変わりません。
