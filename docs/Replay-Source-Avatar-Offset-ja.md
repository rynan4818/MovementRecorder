# コピー元アバターのHMDオフセット・設定保存：実装・検証報告

日付：2026-09-13。対象：MovementRecorder `BS1.29.1`、Beat Saber 1.29.1。

同日追加：XYZの調整を0.1 m刻みへ変更した。以下は最初のオフセット実装時の検証記録。追加修正と最新の成果物は [0.1 m刻みへの変更報告](Replay-Offset-Step-01m-ja.md) を参照。

設計計画書 第2版に対する「OKです進めてください」を受けて実装した。

## 変更内容と使い方

- リプレイメニューの「鑑賞設定」に「コピー元アバターにHMDオフセットを適用」を追加した。初期値はOFF。
- 「コピー元アバターを表示」とオフセット適用を両方ONにすると、コピー元の表示位置にHMDと同じX・Y・Z値を加える。回転やルーム補正による二重適用は行わない。
- コピー元表示がOFF、オフセット適用がOFF、XYZがすべて0のいずれかでは、オフセット用オブジェクト・コールバック・フレーム処理を生成しない。オフセット専用の階層探索・座標保存も行わない。
- 再生中にXYZをすべて0にすると、位置を復元して専用処理を解除する。0以外に戻すと、再生開始時のON/OFF設定に従って再準備する。
- コピー元は一時停止・シーク・末尾停止中も現在のプレイヤーに追従する。記録動作を再生する複製アバターは記録された位置に表示する。

| コピー元表示 | オフセット適用 | コピー元の表示位置 | オフセット専用処理 |
| --- | --- | --- | --- |
| OFF | OFF / ON | 非表示 | 生成しない |
| ON | OFF | アバターMODが更新した位置 | 生成しない |
| ON | ON、XYZすべて0 | アバターMODが更新した位置 | 生成しない |
| ON | ON、XYZに0以外あり | アバターMODの位置 ＋ HMDオフセット | 描画時だけ移動・復元 |

ON/OFFは次のリプレイ開始時に反映する。鑑賞設定内のヘルプにも反映時期を記載した。再生中のXYZ調整はその場で反映する。

## 保存する設定

既存の `UserData/MovementRecorder.json` に次の保存項目を追加した。

| 項目 | 初期値 | 内容 |
| --- | --- | --- |
| `offsetReplaySourceAvatarWithHmd` | `false` | コピー元へのHMDオフセット適用 |
| `replayObserverX` | `0` | 左右、−5〜5 m |
| `replayObserverY` | `0` | 上下、−3〜3 m |
| `replayObserverZ` | `-2` | 前後、−8〜5 m |

鑑賞設定と再生中の操作画面は、保存機能を共通化した `ReplaySession.ObserverX/Y/Z` を通して座標を変更する。`PluginConfig` のvirtualプロパティに変更を反映し、既存のBSIPAの保存機構を利用する。値を参照するだけでは保存対象を更新せず、描画コールバックからの設定書込みもない。

起動時とメニューを開く時に保存値を読み込む。非表示やオフセットOFFでも位置を保存・復元する。新項目がない旧設定では初期値を使い、非有限値は軸ごとの初期値へ、範囲外はUIの上下限へ補正する。実行中の設定ファイル再読込で再生セッションの座標やON/OFFは書き換えない。

## 描画処理と後始末

`SourceAvatarOffset` は、既存のAvatar判定から移動する階層の境界だけを一度作る。親子・兄弟階層のボーンを同じ量だけ移動し、対象の親を共有するOther・実セイバー・実HMD・UIには補正をかけて元の位置を維持する。カメラが含まれる子階層も除外する。

`Camera.onPreCull` で境界の座標を保存し、移動する。`Camera.onPostRender` で元のlocalPositionへ戻すため、通常のIK・Animator・物理更新にはオフセットを残さない。元の姿勢が画面外にある場合にもスキンを更新するため、有効期間のみ対象の `SkinnedMeshRenderer.updateWhenOffscreen` を有効化し、解除時に復元する。

入れ子のカメラを管理し、ミラーで二重移動せず、外側の描画完了まで移動を維持する。終了通知が欠けても、フレーム末尾および次のUpdate・FixedUpdateの早い段階で復元する。この監視コンポーネントも有効期間だけ存在する。

終了・再準備・失敗・破棄時には残っている移動を復元し、専用コンポーネントと描画コールバックを解除する。外部MODが登録したコールバックは保持する。移動対象の消失・階層変更、移動範囲外のボーンは、モデルの対応設定で確認できるエラーとして扱う。

アバター本体のTransformとスキンを移動する。ワールド座標で保持されるパーティクルやTrailの履歴データは書き換えないため、固有の追加エフェクトはモデルごとの実機確認が必要となる。

## 検証結果

- 自動テスト150件成功、失敗・スキップ0件。直前の126件から24件を追加し、既存のメニュー設定スナップショットのテストも拡張した。
- 非表示・OFF・0の各条件について、専用オブジェクト・描画コールバックがなく、60フレーム相当の呼出しでTransform位置の読取り・書込みが増えないことを確認した。
- HMDとコピー元の相対位置、ポーズ・シーク・末尾停止、親の回転・スケール、兄弟のボーン、除外する子階層、二重適用防止、復元と再有効化を確認した。
- 設定値の変更・シリアライズ往復・次セッションへの復元、古い設定の初期値、不正数値、外部再読込時の実行中セッション保持、値の参照による書込みがないことを確認した。
- Visual Studio Releaseビルド成功。既存のMSB3277（System.Net.Http参照バージョン競合）警告は残る。
- 導入済みDLLとのAPI照合277項目成功。カメラ描画コールバック、スキン更新フラグ、フレーム末尾処理、保存対象のvirtualプロパティ、BSMLバインディングを含む。
- Camera2・CameraPlus・アバターMODへのAssemblyRefと必須依存は追加していない。プラグインのversion `0.2.4`、gameVersion `1.20.0` を維持した。

テストは製品コードとUnity等の代替APIで実行している。BSIPAによる実ファイルへの書込み、ゲーム再起動後の復元、Unityのスキニング・XRの実行順、カメラMODと床ミラーの実描画は未確認。これらは自動テストとAPI照合では証明しない。
